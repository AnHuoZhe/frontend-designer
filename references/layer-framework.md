# 五层设计框架详解

> 从骨架到皮肤，逐层穿衣服。每层生成三版选项，用户选一。

## 框架原理

设计的决策不是平级的——有先有后，有上游有下游。上游定了下游才能定。

错误做法：一次性生成三套完整设计让用户选。"你喜欢A的布局但B的配色"——无法组合。

正确做法：逐层收敛。第1层锁定→第2层在锁定约束下生成三版→第3层再锁→……最终自然收敛为一个完整设计。

## 层级依赖关系

五层不是线性流水线，而是一个有向无环图（DAG）：第1层确定信息取舍，第2层确定用户如何在功能间移动；第3层和第4层在第2层锁定后可并行生成；第5层只在第3、4层都锁定后生成。

```text
第1层（信息优先级） ──→ 第2层（交互流程）
                              ├──→ 第3层（空间分配） ──┐
                              └──→ 第4层（组件表达） ──┴──→ 第5层（视觉皮肤）
```

- 第3层和第4层互不依赖，可并行生成。
- 第2层选择不合适时，只需推倒第3层或第4层中的冲突分支；是否两者都重做取决于冲突程度。
- 下层选择与上层锁定结果冲突时，提示用户回退调整上层，而不是在下层强行修补。
- 第5层只依赖第3层和第4层的锁定结果，不直接依赖第1层和第2层。

以 death-replay-agent 为例：第1层锁定“数据优先”后，第2层才比较单页、多 Tab 和“主从双区”；选定“主从双区”后，第3层才生成窄侧边栏、宽侧边栏、无侧边栏三版空间方案，第4层则可同时基于该交互流程和功能清单生成 Table、Card、List 三版组件方案。第3层与第4层锁定后，才生成暗色冷调、暗色暖调、暗色品牌调三版视觉皮肤。

## 第1层：信息优先级

决策问题：用户第一眼最需要看见什么？

输入：阶段A的功能清单

生成逻辑：
- 分析每个功能的使用频率和重要性
- 按"每次都用/偶尔用/很少用"分级
- 三版差异：哪些功能放在首屏、哪些折叠、哪些放到二级页面

三版示例（以death-replay-agent为例）：

**A版——数据优先**
```
首屏：统计概览卡片（胜率、K/D、场均死亡数） + 最近demo列表
折叠：平台选择、API配置
二级：单条死亡详情
```

**B版——操作优先**
```
首屏：Demo库（搜索+列表，默认展开）+ 分析按钮
折叠：统计概览
二级：分析结果详情
```

**C版——概览优先**
```
首屏：一个大卡片——"最近一场"的摘要 + 快速操作入口（分析这一场 / 浏览全部）
二级：完整列表 + 统计
```

用户选一后，该版的优先级逻辑写入 `.frontend-designer` 的 `layers.1_priority`。

## 第2层：交互流程

决策问题：用户怎么在不同功能之间移动？

输入：第1层选定的优先级 + 功能清单

生成逻辑：
- 主流程是什么（最常用的操作路径）
- 分支流程是什么（偶尔用的操作路径）
- 哪些操作在同一页面内完成，哪些需要跳转

三版示例：

**A版——单页滚动**
```
┌──────────────────────┐
│  Dashboard           │
│  ┌───┬───┬───┐      │
│  │统计│统计│统计│      │
│  └───┴───┴───┘      │
│  Demo列表             │
│  (滚动下去是分析配置)    │
│  分析配置              │
│  分析中...             │
│  分析结果              │
└──────────────────────┘
一页到底，所有内容从上到下排列。适合功能少（3-5个）的项目。
```

**B版——多Tab切换**
```
┌──────────────────────┐
│ [概览] [Demo库] [配置]  │
├──────────────────────┤
│                      │
│  当前Tab的内容         │
│                      │
└──────────────────────┘
顶部Tab切换，每个Tab独立一个功能模块。适合功能中等（5-8个）的项目。
```

**C版——主从双区**
```
┌────────┬─────────────┐
│        │             │
│ Demo库 │  选中后的    │
│ (列表) │  详情/操作   │
│        │             │
│        │             │
└────────┴─────────────┘
左侧固定导航，右侧根据左侧选择变化内容。适合功能多（8+）或强调浏览→操作的流程。
```

## 第3层：空间分配

决策问题：屏幕空间怎么分？

输入：第2层选定的交互流程

生成逻辑：
- 如果第2层选了"主从双区"→这层决定左侧多宽、右侧是卡片还是全幅
- 如果第2层选了"单页滚动"→这层决定每段的高度、卡片密度
- 响应式考虑（如果用户需要移动端支持则加入）

三版示例（以主从双区为例）：

**A版——窄侧边栏**
```
┌───┬──────────────────┐
│250│                  │
│px │   主内容区        │
│   │   1200px         │
│   │                  │
│折 │                  │
│叠 │                  │
│面 │                  │
│板 │                  │
└───┴──────────────────┘
侧边栏窄（250px），内容轻量，适合导航项少于5个的场景。
```

**B版——宽侧边栏**
```
┌──────┬───────────────┐
│ 380  │               │
│  px  │   主内容区     │
│      │   1070px      │
│ 列表  │               │
│ 搜索  │               │
│ 筛选  │               │
│      │               │
└──────┴───────────────┘
侧边栏宽（380px），内嵌搜索和筛选，适合侧边栏本身就是主要操作区的场景。
```

**C版——无侧边栏**
```
┌──────────────────────┐
│  顶部导航 + 搜索      │
├──────────────────────┤
│                      │
│   全幅主内容区        │
│                      │
│                      │
└──────────────────────┘
无侧边栏，顶部导航+搜索，内容全幅展开。适合展示密集型（如仪表盘、数据看板）。
```

## 第4层：组件表达

决策问题：同一功能用什么组件来呈现？

输入：第3层选定的空间分配 + 功能清单

生成逻辑：
- 查 `component-mappings.md` 获取每种功能的候选组件
- 根据用户偏好和历史选择推荐
- 三版差异：同一功能用不同组件呈现

三版示例（以Demo列表功能为例）：

**A版——Table表格**
```
┌──────────────────────────────┐
│ 搜索 [___________] [筛选 ▼]  │
├────┬──────────┬──────┬───────┤
│日期 │ 地图      │ K/D  │ 操作  │
├────┼──────────┼──────┼───────┤
│7/15│ Mirage   │ 1.42 │ [分析] │
│7/14│ Inferno  │ 0.87 │ [分析] │
│7/13│ Dust2    │ 2.10 │ [分析] │
└────┴──────────┴──────┴───────┘
适合：数据量大（20+条）、需要排序/比较、需要批量操作
```

**B版——Card卡片**
```
┌────┐ ┌────┐ ┌────┐
│地图 │ │地图 │ │地图 │
│K/D │ │K/D │ │K/D │
│日期 │ │日期 │ │日期 │
│[分析]│ │[分析]│ │[分析]│
└────┘ └────┘ └────┘
适合：数据量少（<20条）、每条有视觉元素（如地图缩略图）、强调浏览而非比较
```

**C版——List列表**
```
┌──────────────────────┐
│ ● 7/15 Mirage  1.42  │
│   2击杀 1助攻 3死亡   │
│   [分析]             │
├──────────────────────┤
│ ○ 7/14 Inferno 0.87  │
│   1击杀 0助攻 2死亡   │
│   [分析]             │
└──────────────────────┘
适合：条目有次级信息需要展示、表单式操作多于浏览
```

## 第5层：视觉皮肤

决策问题：颜色、圆角、间距、字体。

输入：前4层全部锁定后的完整结构

生成逻辑：
- 读取 frontend-preferences.json 中的颜色偏好
- 考虑用户最初提到的风格倾向（极简/专业/活泼/暗色系）
- 三版差异：配色和氛围

三版示例：

**A版——暗色冷调**
```
背景: slate-950/900
卡片: slate-800
强调: cyan-400
文字: slate-100/400
边框: slate-700
圆角: rounded-lg (8px)
```

**B版——暗色暖调**
```
背景: neutral-950/900
卡片: neutral-800
强调: amber-400
文字: neutral-100/400
边框: neutral-700
圆角: rounded-lg (8px)
```

**C版——暗色品牌调**
```
背景: stone-950
卡片: stone-800
强调: pink-500 + cyan-400(辅助)
文字: stone-100/400
边框: stone-700
圆角: rounded-xl (12px)
```

## 审查要点

每层生成后自查：
1. 三版之间有足够差异（不是微调参数）
2. 每版都完整可落地（不是只画了部分功能）
3. 文字说明清晰——一个不懂前端的用户能看懂三版的区别
4. 每版标注适合什么场景（帮助用户做选择）
