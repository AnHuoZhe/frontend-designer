# death-replay-agent：五层设计完整示例

本例展示从后端提取结果到单一前端设计的逐层收敛过程。每一层先给出三版可选方案，再记录用户选择；第3层和第4层在第2层锁定后可并行产出。

## 功能清单

| 功能 | 端点 | UI 模式 |
| --- | --- | --- |
| Demo 库列表 | `GET /api/library` | `table_with_search_filter` |
| 平台目录 | `GET /api/platforms` | `checkbox_list` |
| 分析配置 | `POST /api/config` | `form` |
| 触发分析 | `POST /api/library/{id}/analyze` | `button_with_progress` |
| 分析结果 | `GET /api/analysis/{id}` | `card_with_accordion` |

## 第1层：信息优先级

### A. 数据优先

```text
+------------------ 统计概览 ------------------+
| 胜率 | K/D | 场均死亡 | 最近分析             |
+------------------ Demo 列表 ------------------+
```

适合频繁比较表现数据的玩家。

### B. 操作优先

```text
+------------------ Demo 库 --------------------+
| 搜索 / 筛选                         [分析]     |
+-----------------------------------------------+
```

适合以选择 Demo 并立即发起分析为主的用户。

### C. 概览优先

```text
+--------------- 最近一场摘要 ------------------+
| 关键死亡回放                     [分析这一场] |
+------------------------------------------------+
```

适合偶尔查看近期结果的用户。

**选择：A 数据优先。** 首屏先回答“最近打得怎么样”。

## 第2层：交互流程

### A. 单页滚动

```text
概览 → Demo 列表 → 分析配置 → 分析中 → 分析结果
```

适合功能少、希望上下连续浏览的场景。

### B. 多 Tab

```text
[概览] ↔ [Demo 库] ↔ [配置] → [分析结果]
```

适合各功能相对独立的场景。

### C. 主从双区

```text
Demo 列表（主） ── 选中 Demo ──→ 详情 / 配置 / 结果（从）
```

适合“浏览 Demo → 选择 → 分析 → 阅读结果”的连续任务。

**选择：C 主从双区。** 后续第3、4层均以此锁定结果为输入。

## 第3层：空间分配

### A. 窄侧边栏（250px）

```text
[ Demo 列表 250px ][ 详情、配置和结果 其余宽度 ]
```

导航项少，给详情更多阅读面积。

### B. 宽侧边栏（380px）

```text
[ 搜索、筛选、Demo 列表 380px ][ 详情、配置和结果 ]
```

筛选和列表是高频操作，左侧本身就是主要工作区。

### C. 无侧边栏 + 顶部导航

```text
[ 顶部导航 / 搜索 ][ 全宽内容区 ]
```

适合更偏概览而非持续浏览的页面。

**选择：A 窄侧边栏。** 仅保留选择上下文，把宽度留给死亡回放与结果。

## 第4层：组件表达

### A. Table 表格

```text
| 日期 | 地图 | K/D | 平台 | 操作 |
| 7/15 | Mirage | 1.42 | Steam | 分析 |
```

适合排序、比较和较多 Demo。

### B. Card 卡片

```text
[ Mirage ][ K/D 1.42 ][ 7/15 ][ 分析 ]
```

适合 Demo 附带地图缩略图或视觉摘要。

### C. List 列表

```text
▶ 7/15 Mirage · K/D 1.42                    [分析]
```

适合移动式、快速浏览的行式操作。

**选择：A Table + 详情 Card。** 这是从 A 版和 B 版中各取所需的用户组合：主区用表格比较，右侧分析结果以可展开 Card 呈现。

## 第5层：视觉皮肤

| 版本 | 背景 | 卡片 | 强调色 | 文字 | 边框 | 圆角 |
| --- | --- | --- | --- | --- | --- | --- |
| A 暗色冷调 | `slate-950/900` | `slate-800` | `cyan-400` | `slate-100/400` | `slate-700` | `rounded-lg (8px)` |
| B 暗色暖调 | `neutral-950/900` | `neutral-800` | `amber-400` | `neutral-100/400` | `neutral-700` | `rounded-lg (8px)` |
| C 暗色品牌调 | `stone-950` | `stone-800` | `pink-500` + `cyan-400` 辅助 | `stone-100/400` | `stone-700` | `rounded-xl (12px)` |

**选择：C 暗色品牌调。** 它建立游戏分析产品的辨识度，同时用 cyan 保留数据状态的清晰层级。

## 最终组合布局

```text
+---------------------+------------------------------------------+
| Demo 库（250px）     | 数据概览：胜率 / K/D / 场均死亡           |
| 搜索、平台筛选       +------------------------------------------+
|                      | 选中 Demo 详情                            |
| Table：日期/地图/KD  | [分析] 进度 → 结果 Card → 死亡回放折叠项 |
|                      |                                          |
+---------------------+------------------------------------------+
```

最终决策路径：数据优先 → 主从双区 → 窄侧边栏 → Table + Cards → 暗色品牌调。
